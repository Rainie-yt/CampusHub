# 启动时的数据保护修复（2026-11-15）

此前，主程序忽略成员、加入申请和活动加载的失败结果；社团加载失败时也会继续运行。
损坏文件可能因此被空列表或部分加载的数据覆盖，造成成员、活动和报名丢失。

## 当前行为

- 所有业务数据校验成功后才进入登录/注册菜单、补充历史注销名单。
- 已有文件无法读取或记录无效时，报告文件名、行号（读取失败时只有文件名）和原因，返回非零退出码；不修改任何数据文件。
- 只有文件不存在时才按空数据处理。如果其他文件仍引用其中不存在的记录，会报告引用错误并停止启动。例如活动文件缺失而报名文件仍有报名记录时，不能忽略这些报名。
- 社团记录之间、文件末尾的空行正常忽略；记录内部仍固定七行，普通社团的第二行分类资料必须为空。
- 社团成员、加入申请每行严格两个编号；重复记录、不存在的社团和非法成员/申请均报错。
- 活动和报名必须全部校验通过后才共同替换内存。失败时保留之前的活动、报名、候补和下一编号，不跳过坏行继续加载。
- 账号文件增加启动校验，检查缺少字段、重复Id、非法角色/状态等，避免错误账号数据参与历史注销Id迁移。兼容没有状态列的旧六字段账号。
- 社团、成员、申请、活动和报名支持CRLF与文件头UTF-8 BOM。账号的现有读取入口不支持BOM，因此会明确提示将users.txt保存为不带BOM的UTF-8，防止Id被误读。含空字节的文件被拒绝。

现有的保存临时文件、替换及普通I/O失败回滚机制继续使用。此补丁不增加每次保存的.bak文件；安装前会单独备份将被替换的文件。仍按单进程使用，不提供多实例并发写入或断电恢复。

## 构建与复测

从项目根目录运行：

```powershell
.\build.ps1
python tests/regression.py --exe .\campushub.exe
python tests/data_protection.py --exe .\campushub.exe
```

本次Windows g++构建通过；原有40项回归检查与新增44项数据保护检查全部通过。
新增测试使用临时目录和合成数据，验证异常启动不进入菜单、不改写文件、不提前写入注销名单；
也覆盖文件被目录替代、Windows文件独占锁、社团末尾空行、编号不复用、缺失文件初始化、旧账号格式兼容。
使用现有业务数据的独立副本启动并退出成功，副本所有数据文件保持不变。

原活动文档中“坏行跳过，正常数据继续加载”的行为已改为严格失败处理；未复跑未提供源码的原85项测试。

## 遇到提示时

先按提示检查对应文件和行号，参考同文件相邻记录修复格式，或从可信备份恢复后重新运行。
不要为了让程序启动而清空文件；程序不会自动删除坏记录或修复历史业务归属。

本次只修复数据加载保护；过期的待审核活动处理和菜单/提示文案问题另行处理。
