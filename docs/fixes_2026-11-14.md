## 最终采用的业务规则

- 用户注销：将 ID 写入 `data/retired_user_ids.txt`，每行一个 ID。注册同时检查现有用户和永久注销名单；删除账号与写入名单统一提交。历史活动记录保持原格式。
- 兼容旧数据：启动时扫描历史活动和当前社团关系中已不存在的用户 ID，补入名单，防止修复前遗留的记录被新账号继承。无法检查名单时停止启动，避免绕过检查。
- 活动修改：未结束活动修改后回到 pending，保留报名、候补和时间预约，暂停新报名。有人报名或候补时仍不能修改活动时间。审核通过后恢复报名，并按名额递补；驳回后可修改再送审，也可从负责人活动菜单 6 重新提交原编号。
- 历史活动：已结束活动禁止修改，避免修改内容或审核状态影响既有积分。
- 社团解散：管理员菜单 2 → 3，明确确认后清空成员和加入申请，取消所有未结束活动及其报名；已结束活动和对应积分保留。社团本身保留为 `dissolved` 归档，避免历史活动指向被重新分配的社团编号。
- 负责人角色：正常社团审核要求申请人是现有普通学生；待审核成立申请处理前不能切换角色。解散后，原 ClubManager 恢复为 Student（如仍管理其他通过社团则保留）。
- 保存结果：用户、社团、活动保存先写临时文件，再替换；普通 I/O 失败时恢复已替换文件，内存也回滚。管理员审核、用户删除和社团解散的关联文件统一提交；失败不显示成功。

新保存工具面向单进程使用；没有实现多进程并发写入协调或断电恢复日志。不要同时运行多个程序修改同一 data 目录。

## 构建和回归

在项目根目录运行：

```powershell
.\build.ps1
python tests/regression.py --exe .\campushub.exe
```

构建使用 Windows g++、C++11、UTF-8 输入输出字符集，并静态链接运行库。现有社团模块的有符号/无符号比较警告仍保留。

回归脚本使用临时目录和合成账号，不操作项目 data 文件。40 项检查覆盖正常报名/候补/冲突/递补、社团成立和成员审核、活动发布审核推荐、注销名单与重启、旧数据兼容、角色覆盖保护、重新送审、历史积分保留、解散取消，以及多种只读文件导致的保存失败与回滚。

原文档提到的 test_activity.cpp/85 项测试源码仍未提供。本次 tests/regression.py 是新增的独立回归脚本，不代表复跑了原来的 85 项测试。
